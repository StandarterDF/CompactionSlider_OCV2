# Изменения (незакоммичено)

## 0.2.1

- Плагин оставляет только слэш-команду `/ctx-percent` (алиас `/ctxpct`):
  запись убрана из палитры команд и из подсказок.

## 0.2.0

- Максимум слайдера поднят с 95 % до **99 %**.
- Появилась точная настройка: ниже 95 % шаг 5 %, с 95 % — 1 %
  (настраивается через `fineFrom` / `fineStep`). Стрелки переходят через
  границу точно на 95 %.
- Новый помощник `movePercent` (пошаговое движение по адаптивной сетке) и
  юнит-тесты на него.
- Диалог перерисован: заголовок с процентом, шкала с подписями
  `10 % / тонко с 95 % / 99 %`, строки «Сейчас», «Станет», «Compaction»,
  разделители, кнопки-чипы и подсказка с текущим шагом.
- Состояние отдаёт `currentPercent` (реальный процент модели, даже если он вне
  диапазона слайдера), чтобы строка «Сейчас» не врала для неуправляемой модели.
- README: раздел «Почему compaction наступает раньше лимита» и совет уменьшить
  `compaction.buffer`.

## 0.1.0

- Первая версия плагина `opencode.compaction-slider`.
- TUI-команда `/ctx-percent` (алиас `/ctxpct`) открывает диалог со слайдером
  порога авто-compaction: 10–95 %, шаг 5 %.
- 100 % — реальный максимум контекста модели из каталога провайдера
  (models.dev), а не `limit.context` из `opencode.json`.
- Значение хранится по модели (`provider/model`) в `ctx.storage`, применяется
  через `ctx.model.transform` и `ctx.model.reload()` без перезапуска.
- Выставляются `limit.context` и `limit.input`; compaction считается от
  `limit.input`, который не перекрывается конфигом.
- Диалог показывает абсолютный лимит, исходный максимум и оценку порога
  срабатывания compaction (`max(16k, 15 %)` буфер).
- «Сброс» возвращает модель к лимиту из конфига.
- Предупреждения о конфликте с `limit` в `opencode.json`.
- Опции `min`/`max`/`step`/`providers`/`models`, отладочный лог
  `COMPACTION_SLIDER_DEBUG`.
- Юнит-тесты `tests/settings.test.mjs`.
